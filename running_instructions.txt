Reproducing the figures and tables

This folder contains the code and archived data for Figures 1-8 and S1-S12,
and Tables 1-6 and S1-S22 in the MH manuscript. Every numbered output has a
matching Python script in its output directory. For example:

Figures/generate_figure_05_climate_index_correlations.py
Figures/figure_05_climate_index_correlations.png
Figures/figure_05_climate_index_correlations.pdf

Tables/generate_table_s20_el_nino_winter_classification.py
Tables/table_s20_el_nino_winter_classification.docx

Keep Code, Data, Figures and Tables together when copying the project.
Paths are resolved from the scripts, so they also run from another directory.
The source workbook and manuscripts are never overwritten by these scripts.

Installation

The calculations were checked with Python 3.12 and the package versions in
requirements.txt. From Reproducibility, create a separate environment and install:

  python -m venv .venv
  .venv\Scripts\python -m pip install -r requirements.txt

On macOS or Linux, use .venv/bin/python instead of .venv\Scripts\python.
Microsoft Word and Excel are not required to generate the files. A compatible
Word viewer is needed to inspect DOCX layout. Font and software differences
can affect appearance; the numerical checks are independent of rendering.

Run one output

  .venv\Scripts\python Figures/generate_figure_05_climate_index_correlations.py
  .venv\Scripts\python Tables/generate_table_s20_el_nino_winter_classification.py

These commands replace only the named derived figure pair or table document.
Close that output in Word or a PDF viewer before replacing it.
To keep the saved outputs, add --output-dir followed by a separate folder:

  .venv\Scripts\python Code/reproduce.py --figure 5 --output-dir ../Reproducibility-Rebuilt
  .venv\Scripts\python Code/reproduce.py --table S20 --output-dir ../Reproducibility-Rebuilt

The destination contains Figures and Tables subfolders. Numbers are case
insensitive; 5, 05, S5 and s05 are accepted for their respective sequences.

Run the complete study

  .venv\Scripts\python Code/reproduce.py --all --check --export-data --output-dir ../Reproducibility-Rebuilt

This produces 20 PNG/PDF figure pairs, 28 DOCX tables and 27 recalculated CSVs.
The 28 numbered tables contain 38 physical tables because some have panels.
The rebuilt tables retain the captions, notes, headings and cell contents;
their standalone Word formatting is recreated and need not match the
reviewed manuscript layout. The command does not insert outputs into the manuscript.

Other commands

  .venv\Scripts\python Code/reproduce.py --list
  .venv\Scripts\python Code/reproduce.py --check
  .venv\Scripts\python Code/reproduce.py --help

--list prints every numbered output and its script path.
--check recalculates all 27 datasets and compares their shapes, labels and
numeric values with Data/*.csv (absolute tolerance 1e-12, relative 1e-10).
An error stops the check; successful completion reports that inputs are
unchanged. --check alone does not create or replace any file.
--export-data writes recalculated CSVs only to a separate output directory.
Assertions are part of the numerical checks; do not run Python with -O.

OLR daily-coverage sensitivity (Supplementary Section S1.2)

  .venv\Scripts\python Code/olr_coverage_sensitivity.py
  .venv\Scripts\python Code/olr_coverage_sensitivity.py --export

The first command recalculates and checks the comparison without writing files.
The second also saves these derived comparisons in Sensitivity:
  olr_winter_daily_coverage.csv                 44 winters and daily counts
  olr_coverage_trend_family_comparison.csv      44 family/specification rows

The routine identifies incomplete winters from the daily workbook observations;
1984, 1985 and 1986 are excluded only in the OLR sensitivity. No values are filled
or changed. Winter means keep equal monthly weights. Slopes use actual years;
lag-one residual pairs must be one calendar year apart. No pre-whitening is
triggered for these retained samples. The code stops if that screening outcome
changes, because a gap-aware filtering method would require separate review.
The two original eleven-index trend families are recalculated, replacing only
the OLR probability before Benjamini-Hochberg adjustment. The original 27 CSVs
are preserved. Sensitivity CSV slopes use each index's native units per decade
(Table 2); OLR uses watts per square metre per decade. Extra lag-pair/threshold
fields apply only to the complete-coverage OLR rows; blanks elsewhere do not
represent missing input observations. Sen intervals are conventional intervals,
not corrected for serial dependence. The comparison does not establish unbiased
missingness or a zero trend.

This separate command is not invoked by Code/reproduce.py --all or --check.
Run it as well when checking all findings in the current reviewed paper.

Data and methods

Data/Climate_Indices_Data.xlsx is the fixed input archive. Its Monthly,
Weekly_SST and Daily_OLR_ElNino sheets supply observations; Metadata supplies
inventory checks, and DJF_seasonal supplies an independent aggregation check.
No online download is needed after installing the packages. The product links
and source qualifications below supplement the workbook metadata and Table 2.

The code verifies this workbook version using SHA-256:
f5223da118589c1723347173f4563b4f1966cd0ab945cf50b934900d13dfcda6

This reproduces the manuscript's archived data, not the latest provider files.
Do not substitute updated observations without reviewing the periods, source
definitions, manuscript claims and expected results. The saved CSVs are used
as comparison results by --check, not as the source of numerical table cells.

Weekly and daily observations are grouped by their timestamp month. Winter
means give equal weight to December, January and February and require all
three monthly values. The winter label is the January year. Shared-index
analyses use 40 winters, 1983-2022. Individual-record trend lengths differ;
the El Nino classification uses 45 winters, 1982-2026. No gaps are filled.

Figure 1 evaluates the Alduchov-Eskridge liquid-water saturation equation; it
is a theoretical illustration. Tables 1 and 6 are literature-based summaries
with their references included. Their wording is stored in table_definitions.py.
Table 2 combines calculated record coverage with the documented index names
and units. All other table rows are calculated from the workbook.

Statistical choices, including the comparison families, conditional
pre-whitening, conventional Sen intervals, Newey-West lag choices, principal
component signs and El Nino thresholds, follow the manuscript methods.
The circular-block calculation uses 10,000 draws and fixed seeds. Rebuilding
the results does not establish causal effects on Canadian river discharge.

Metadata qualifications

AMO is in degrees Celsius and is already detrended. The earlier archived-source
comparison matched 901 workbook months to the unsmoothed PSL short series.
The workbook's 'standardized' metadata label is not adopted for AMO. The PSL
page identifies the Kaplan-based series and its endpoint in January 2023;
do not replace it with an ERSST-based or global-mean-adjusted alternative.

PDO remains on the provider's scale. Its archived variable does not establish
units or a normalization period. The portal's plotted standard-deviation
reference period does not resolve normalization. The workbook's 'standardized'
label alone is insufficient to assign unit variance or a fixed baseline.

Nino 3, Nino 3.4, Nino 4 and TNA use the documented 1991-2020 anomaly reference.
For Nino 1+2, the archived variable/workbook labels say 1982-2020 whereas the
provider page says 1991-2020. Its reference period remains unconfirmed. It is
retained only in the specified trend families, not the joint eight-index
analysis or event classification. Do not relabel or rebase the observations.

The workbook also retains Annual and Annual_OLR_LaNina sheets. Those annual
series are not inputs to these winter calculations. Its general list of
originating centres is not evidence that an NSIDC product was analysed here.
Daily OLR values retain missing observations; the separate sensitivity routine
documents their effect on the specified winter trend comparison. The provider
OLR page's displayed update date is not used as the archived record endpoint.
Coverage in Data/climate_index_inventory.csv is calculated from the workbook.

Relationship to archived source comparisons

The netCDF and PSL text files used in earlier source checks are comparison
archives, not additional independent observations or replacement analysis
inputs. They are not required by this package and have not been copied here.
Earlier checks found a weekly SST difference on 23 August 2026 between the
workbook and later comparison files; it is outside the analysed winters.
The Nino 1+2 winter agreement was rechecked during this review. Those checks
confirm value correspondence over the stated periods, not an independently
verified climatology or the correctness of every upstream observation.
